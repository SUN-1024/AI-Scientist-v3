# 研究质量、预算与下一轮实验

增加 token 和轮次能扩大搜索，但不能保证超过基线。先保证实验有效、比较公平、反馈足够，再增加搜索。第一次 PathMNIST 案例是流程连通检查：两个候选、一个验证 seed、每条件最多 160 steps。它不足以判断融合系统的上限。

## 第一次为什么没有成功

| 观察 | 可以判断什么 | 不能判断什么 |
|---|---|---|
| 两个候选均未超过基线均值 | 这两个候选在当时的小预算设置下没有获胜 | 该研究方向没有价值，或更大预算一定有效 |
| 两个候选改善噪声条件，却损失更多干净标签性能 | 需要看逐条件反馈，不能只看总分 | 稀疏聚合普遍无效 |
| 只使用一个验证 seed | 排名可能受随机初始化和训练采样影响 | 当前差距稳定或显著 |
| 某些最优 checkpoint 出现在步数上限 | 需要做共享预算的训练校准 | 增加步数必然有收益 |
| 一次 502 占用了一个 idea cycle | 执行失败减少了实际方法比较次数 | 该 idea 的科学假设失败 |
| 加背景后阴性概率升幅更大 | 类间分离变化比只看阳性概率更有用 | 已证明是“阳性证据被稀释”机制 |

原始结果和冻结代码见[首次案例报告](pathmnist-mil-pilot-2026-10-18.md)。旧留出集已经查看，后续开发不再用它选方法。反复搜索同一验证集会增加选择偏差；正式结论需要未用于搜索的独立确认数据。[Cawley 与 Talbot，JMLR 2010](https://www.jmlr.org/beta/papers/v11/cawley10a.html)

## 四类预算要分别设置

| 层次 | 配置位置 | 扩大后改变什么 |
|---|---|---|
| 文献检索 | `research.yaml` 中的 `literature.model_search` | 输出长度、联网调用次数、检索模型的推理强度 |
| Idea 与编码 | preset 中的 `agent.reasoning_effort`、idea/run timeout | 每次提出与实现方法的推理时间 |
| 实验搜索 | `max_idea_cycles`、`research.yaml` 的 `search` | 尝试次数、候选父分支池、探索频率 |
| 科学评价 | 冻结任务内的 `evaluation_protocol.json` | 每个方法的 seed 数、训练步数、早停与优化设置 |

只增加 `max_output_tokens` 不会增加训练步数或搜索轮次。树的 `width` 是父分支候选池宽度，不是每轮同时生成多少个方法。多 worker 使用独立实验树；当前不是共享树的 MCTS。全局轮次预算也不是每个 worker 各得到一份。

本机研究 preset 为 [pathmnist_mil_research.yaml](../configs/preset/pathmnist_mil_research.yaml)：高推理强度、24 个调度轮次、单 worker、每个候选一次宿主评价。一次宿主评价内部可以运行多个固定 seed。不能用增加 `max_program_evals_per_attempt` 代替多 seed 协议。

## 建议的运行顺序

1. **校准。** 用同一个评价器，对基线和已有对照比较 160、320、640 steps。各设置使用相同的三个 seed。只读取开发数据。先保存比较计划和文件哈希，再训练。
2. **冻结。** 在新任务目录确定评价协议、文献配置与研究目标。不要改变已冻结的 `input_task`。训练预算应来自校准证据，不能只因为预算充足就不断增加。
3. **探索。** 先复现一个有解释力的已知对照，再比较不同机制。低分但有效的分支可继续探索。每个 idea 说明预期收益、可能失败的原因与判别指标。
4. **细化。** 根据逐 seed、逐噪声结果改进最有希望的方法。临时 API 错误在同一 idea 内重试；无效或低分实验仍保留。
5. **确认。** 固定候选后，用独立数据、重复训练、匹配容量与训练预算的对照检查收益。确认集结果不能再回传给搜索。

这是研究流程安排。当前树策略和阶段提示还不是完整的 V2 自适应实验管理器。V2 包含渐进式实验管理与树搜索；本项目仍需通过多任务、同预算比较验证融合收益。[V2 论文](https://arxiv.org/abs/2504.08066)

## 如何扩大搜索

首次运行先用小轮数验证配置。准备任务和协议的方法见[案例操作说明](../examples/pathmnist_mil/README.md)。通过后可在同一未改变的输入上增加搜索轮数：

```bash
./scripts/research-agent run --resume results/unified/pathmnist-mil-research \
  investigation.execution.max_idea_cycles=24
```

`--resume` 延用保存的模型、preset 和任务输入。若改变 seed、训练步数、特征或文献，应创建新工作区。旧结果和新结果需重新做匹配比较。原生模式不提供容器隔离；正式研究使用容器和封闭最终评估。

API 预算可以很大，但仍保留清楚的运行边界：每批结束先检查有效实验数、错误率、每次改进的成本和验证集复用次数。无收益时，应改变可检验假设、特征或任务设计，而不是无限重复相近候选。更强的特征、真实 WSI 和患者划分是后续研究方向，尚未在这个快速案例中验证。
